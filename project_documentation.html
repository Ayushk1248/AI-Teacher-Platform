Technical Reference

Lumina — AI Teacher Platform

Complete Technical Architecture, File Structure, Security Model & Database Reference

1. Technology Stack

Framework & Core

Next.js 16.3.3 (App Router with Turbopack), React 19, TypeScript 5.7.3

Styling & UI

Tailwind CSS v4 (`@tailwindcss/postcss`), Lucide React icons, Base UI primitives

Backend & Storage

Supabase PostgreSQL Database, Supabase Auth (`@supabase/ssr`), Supabase Private Storage

Authentication

OAuth 2.0 (Google, GitHub), Email/Password sign-in, NextAuth v5 integration

3. Database Schema & RLS Security

Table Name Primary Key Foreign Keys / References Purpose & RLS Rule
profiles id (UUID) auth.users(id) (Cascade) Stores username, display name, email. RLS: auth.uid() = id
courses id (UUID) created_by → profiles(id) Stores course metadata & default demo courses. RLS enabled.
lessons id (UUID) course_id → courses(id) Lesson steps, order index, content payload.
user_courses id (UUID) user_id → profiles(id), course_id → courses(id) Student course enrollments. RLS: auth.uid() = user_id
lesson_progress id (UUID) user_id → profiles(id), lesson_id → lessons(id) Tracks status, current phase, paused state, snapshot JSON. RLS enabled.
assessments id (UUID) user_id → profiles(id), lesson_id → lessons(id) Historical assessment scores. RLS: auth.uid() = user_id
materials id (UUID) user_id → auth.users(id) (Cascade) Document metadata & storage path. RLS: auth.uid() = user_id
assessment_results id (UUID) user_id → auth.users(id) (Cascade) Quiz history, correct/missed items, strong/weak areas. RLS enabled.

Storage Bucket

  • Bucket ID: materials (Private, `public = false`)
  • Folder Path Convention: materials/{user_id}/{uuid}_{filename}
  • Storage RLS: Read, upload, and delete policies enforce (storage.foldername(name))[1] = auth.uid()::text.

4. Authentication & Security Architecture

Middleware Guard

The middleware.ts script intercepts all incoming requests to protected routes (/dashboard, /classroom, /materials, /progress, /settings, etc.). Unauthenticated requests are automatically redirected to /login?callbackUrl=....

Account Deletion & Data Wiping

Account deletion is executed exclusively on the server via POST /api/auth/delete-account:

  1. The caller's session is validated via cookies using supabase.auth.getUser().
  2. The user's private files are removed from Supabase Storage.
  3. The user is deleted from Supabase Auth using the server-only SUPABASE_SERVICE_ROLE_KEY client (admin.deleteUser(userId)).
  4. PostgreSQL ON DELETE CASCADE constraints automatically wipe all corresponding profile, course enrollment, lesson progress, assessment, and material metadata records.

5. Backend API Endpoints Reference

HTTP Method Endpoint Path Authentication Description
GET /api/materials Required (Cookie Session) Returns array of uploaded materials for the authenticated user.
POST /api/materials Required (Cookie Session) Uploads a file to Supabase Storage and records metadata row in DB.
DELETE /api/materials Required (Cookie Session) Removes file from Storage and deletes DB record.
GET /api/progress/assessment Required (Cookie Session) Retrieves the latest assessment result for a given lessonId.
POST /api/progress/assessment Required (Cookie Session) Scores checkpoint answers, generates strong/weak report, and upserts to DB.
POST /api/auth/delete-account Required (Cookie Session) Deletes all user files and purges the auth account permanently.
