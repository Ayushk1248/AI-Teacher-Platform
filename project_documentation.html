3. Database Schema & RLS Security

Table Primary Key Foreign Keys Purpose & RLS Rule
profiles id (UUID) auth.users(id) Cascade Username, display name, email. RLS: auth.uid() = id
courses id (UUID) created_by → profiles(id) Course metadata & demo courses. RLS enabled.
lessons id (UUID) course_id → courses(id) Lesson steps, order index, content payload.
user_courses id (UUID) user_id → profiles(id), course_id → courses(id) Student enrollments. RLS: auth.uid() = user_id
lesson_progress id (UUID) user_id → profiles(id) Current phase, paused state, snapshot JSON. RLS enabled.
assessments id (UUID) user_id → profiles(id) Historical scores. RLS: auth.uid() = user_id
materials id (UUID) user_id → auth.users(id) Cascade Document metadata & storage path. RLS: auth.uid() = user_id
assessment_results id (UUID) user_id → auth.users(id) Cascade Quiz history, strong/weak areas. RLS enabled.

Storage Bucket

  • Bucket ID: materials (Private, public = false)
  • Path Convention: materials/{user_id}/{uuid}_{filename}
  • Storage RLS: Read, upload, and delete policies enforce (storage.foldername(name))[1] = auth.uid()::text

4. Authentication & Security Architecture

Middleware Guard

The middleware.ts script intercepts all incoming requests to protected routes (/dashboard, /classroom, /materials, /progress, /settings). Unauthenticated requests are redirected to /login?callbackUrl=....

Account Deletion & Data Wiping

Executed exclusively on the server via POST /api/auth/delete-account:

  1. Caller's session is validated via cookies using supabase.auth.getUser().
  2. User's private files are removed from Supabase Storage.
  3. User deleted from Supabase Auth using SUPABASE_SERVICE_ROLE_KEY admin client (admin.deleteUser(userId)).
  4. PostgreSQL ON DELETE CASCADE constraints automatically wipe all profile, enrollment, lesson progress, assessment, and material metadata rows.

5. Backend API Endpoints Reference

Method Endpoint Auth Description
GET /api/materials Cookie Session Returns array of uploaded materials for the authenticated user.
POST /api/materials Cookie Session Uploads file to Supabase Storage and records metadata row in DB.
DELETE /api/materials Cookie Session Removes file from Storage and deletes DB record.
GET /api/progress/assessment Cookie Session Retrieves latest assessment result for a given lessonId.
POST /api/progress/assessment Cookie Session Scores checkpoint answers, generates strong/weak report, upserts to DB.
POST /api/auth/delete-account Cookie Session Deletes all user files and permanently purges auth account.

8. AI Classroom — State & Engine Architecture

Lesson Phases

The classroom component is driven by a LessonPhase state machine. Valid phases are:

type LessonPhase =
  | 'teaching'      // Maya delivers the teaching narrative
  | 'question'      // MCQ or short-answer question is displayed
  | 'answering'     // User is typing or selecting an answer
  | 'evaluating'    // AI evaluates the submitted answer
  | 'reexplaining'  // Maya re-explains if answer was wrong
  | 'continuing'    // Lesson complete; prompt to start next lesson

MockTeacherEngine (lib/teacher-engine.ts)

The MockTeacherEngine implements the TeacherEngine interface with three methods:

MethodInputReturns
getLessonById(lessonId) TeacherLessonId TeacherLesson — full lesson data including visualPayload
evaluateAnswer(lessonId, selectedIndex) lessonId, user's answer index TeacherEvaluation — feedback, correctAnswer, reexplanation, visualPayload
continueLesson(lessonId) TeacherLessonId LessonContinuation — next lesson ID or completion message

visualPayload Data Flow

TeacherLesson.visualPayload
  → Phase: 'teaching'
  → currentVisualPayload state ← useEffect sync

TeacherLesson.question.visualPayload
  → Phase: 'question' | 'answering'
  → currentVisualPayload state ← useEffect sync

TeacherEvaluation.visualPayload (from question.visualPayload)
  → Phase: 'evaluating' | 'reexplaining'
  → currentVisualPayload state ← useEffect sync

currentVisualPayload → Visual Blackboard container (rendered conditionally)

9. AI Integration Guide — Context for ChatGPT / AI Assistants

This section provides a ready-to-paste prompt and context block that you can hand to ChatGPT (or any AI assistant) to get help implementing real AI capabilities into this platform.

What the Platform Does (Summary for AI)

Lumina is a Next.js 16 + Supabase AI teacher platform. A simulated AI teacher named Maya teaches students interactively. The platform has a working AI Classroom page at app/(app)/classroom/page.tsx with a full lesson state machine (teaching → question → evaluation → continue phases). Currently, all teacher responses (narration, questions, evaluations, re-explanations) are powered by a static MockTeacherEngine in lib/teacher-engine.ts.

The next goal is to replace or augment the MockTeacherEngine with real AI calls (e.g., using Google Gemini, OpenAI GPT-4, or similar) so that Maya's teaching content, questions, and evaluations are generated dynamically based on the student's chosen topic.

Where the AI Agent Is Supposed to Go

  • Primary integration point: lib/teacher-engine.ts — Replace the MockTeacherEngine class methods (getLessonById, evaluateAnswer, continueLesson) with real API calls to an LLM.
  • API route for AI calls: Create a new server-side API route (e.g., app/api/teacher/route.ts) that accepts lesson context and student input, calls the LLM, and returns structured JSON matching the TeacherLesson / TeacherEvaluation TypeScript types.
  • Visual Blackboard payload: The LLM should also generate visualPayload — a markdown code block string that gets rendered in the Visual Blackboard panel next to Maya's avatar. This is already wired up in the UI and ready to receive dynamic content.
  • Streaming support (optional): Maya's narration text (teacherNarrative state variable in the classroom component) can support streamed tokens from the LLM for a more live "typing" effect.
  • Ask Teacher Panel: There is already a slide-over "Ask Teacher" panel (components/app/ask-teacher-panel.tsx) that is waiting to be wired up to an AI Q&A endpoint.
